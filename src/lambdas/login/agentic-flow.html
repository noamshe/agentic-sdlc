The path to production

Our agentic workflow
  1. 1 Create

    Codex builds the idea

    A request becomes a focused change on a new Git branch. Codex follows the project structure, writes the code, and runs relevant local tests.

    Output: a tested branch, ready to share.
  2. 2 Propose

    Open a pull request

    The branch is pushed and a pull request explains the change, its purpose, and how it was tested. The diff makes the proposal easy to inspect.

    Output: a reviewable proposal against main.
  3. 3 Verify

    Two checks, different jobs

    Eligible, non-draft PRs within this repository get complementary checks through GitHub Actions.

    • AI reviewer: reads the PR diff and policy, then posts findings and a review decision.
    • Permission checker: when infra files change, creates a read-only Terraform plan and simulates the deployer's AWS permissions.
    No infra file changes? The permission workflow is skipped. The AI reviewer does not execute PR code.
  4. 4 Decide

    A human merges to main

    Review the findings, fix issues, and re-run checks as needed. A human makes the merge decision, bringing the reviewed change into the main branch.

    AI approval is review feedback; it does not authorize a production deployment.
  5. 5 Deliver

    Terraform ships the change

    After a merge affecting infra or Lambda code, the deployment workflow initializes, validates, and plans Terraform, then applies the saved plan. Lambda packages and infrastructure are updated together.

    The deployment workflow uses its AWS deployment role. Unrelated changes do not trigger it.

Automation with a human at the helm.

Agents accelerate the work. Reviews and permission checks make changes easier to assess. Human judgment remains part of the journey from a request to a release.

This page explains the workflow; it does not start reviews, merge code, or deploy resources.
